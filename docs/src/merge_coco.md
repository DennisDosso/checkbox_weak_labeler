# merge_coco — COCO JSON Merge Utility

## Overview

`src/utils/merge_coco.py` merges two or more COCO JSON annotation files into a
single, coherent output file.

This is particularly useful when different annotation campaigns produce separate
COCO files for the same image set — for example, one file with **signature**
bounding boxes and another with **checkbox** (checked/unchecked) annotations.
The tool deduplicates images, resolves category ID conflicts, and reassigns all
IDs sequentially so the output is always a valid, self-consistent COCO dataset.

No additional dependencies beyond those already listed in `pyproject.toml`.

## How It Works

### 1. Category conflict resolution (by name)

Category identity is determined by **name**, not by numeric ID.

- The first occurrence of a category name across all input files wins the
  **canonical global ID**.
- If the same name appears in multiple files with **different IDs**, all
  occurrences are remapped to the canonical ID — no data is lost.
- If two **different names** share the same numeric ID, one keeps the ID and
  the other is assigned the next available unused ID.

A full per-file remapping table is printed when `--verbose` is used.

### 2. Image deduplication

Images are identified by their `file_name` field.

- If the same `file_name` appears in multiple input files, only **one entry**
  is kept in the output.
- When duplicates exist, the entry with the **larger resolution**
  (`width × height`) is preferred; on a tie, the first occurrence wins.
- All images receive **new sequential IDs** starting from `1`.

### 3. Annotation merging

- All annotations from all input files are combined into a single list.
- Each annotation's `image_id` and `category_id` are rewritten using the
  per-file remapping tables computed in steps 1 and 2.
- All other fields (`bbox`, `area`, `iscrowd`, `confidence`, etc.) are
  preserved exactly as-is.
- Annotations receive **new sequential IDs** starting from `1`.

### 4. Output

The merged file is a standard COCO JSON with the following top-level keys:

| Key | Description |
|-----|-------------|
| `info` | Generated automatically (date, description, version) |
| `licenses` | Always empty (`[]`) |
| `images` | Deduplicated, sequentially re-IDed image list |
| `annotations` | Merged, sequentially re-IDed annotation list |
| `categories` | Conflict-resolved, sorted category list |

## CLI Usage

```bash
python -m src.utils.merge_coco \
    -i path/to/file1.json path/to/file2.json \
    -o path/to/merged_output.json \
    [--verbose]
```

### Arguments

| Argument | Short | Required | Description |
|----------|-------|----------|-------------|
| `--inputs` | `-i` | **Yes** | Two or more input COCO JSON file paths |
| `--output` | `-o` | **Yes** | Destination path for the merged JSON |
| `--verbose` | `-v` | No | Print a detailed per-file category remapping table |

### Examples

**Basic merge of two files:**
```bash
python -m src.utils.merge_coco \
    -i data/_annotations.coco.json data/_annotations.checkboxes.coco.json \
    -o data/merged.json
```

**Merge with verbose conflict report:**
```bash
python -m src.utils.merge_coco \
    -i data/signatures.json data/checkboxes.json data/extra.json \
    -o data/merged.json \
    --verbose
```

## Console Output

After merging, a summary is always printed to stdout:

```
=== COCO Merge Summary ===
Input files      : 2
Total images     : 450 (deduplicated: 12)
Total annotations: 8050
Categories in output:
  [0] signature        (from: _annotations.coco.json, _annotations.checkboxes.coco.json)
  [1] checked          (from: _annotations.checkboxes.coco.json)
  [2] unchecked        (from: _annotations.checkboxes.coco.json)
Category conflicts resolved: 0
Output written   : data/merged.json
```

With `--verbose`, a per-file remapping table is also printed:

```
Category remapping for _annotations.coco.json:
  old id 0 (signature) -> new id 0 (signature)  [no change]
Category remapping for _annotations.checkboxes.coco.json:
  old id 0 (signature) -> new id 0 (signature)  [no change]
  old id 1 (checked)   -> new id 1 (checked)    [no change]
  old id 2 (unchecked) -> new id 2 (unchecked)  [no change]
```

If a category ID was remapped due to a conflict, the tag shows `[REMAPPED]`
instead of `[no change]`.

## Example: merging the checkbox-weak-labeler output files

The two files generated by this project have the following category layouts:

| File | Categories |
|------|-----------|
| `_annotations.coco.json` | `{id: 0, name: "signature"}` |
| `_annotations.checkboxes.coco.json` | `{id: 0, name: "signature"}`, `{id: 1, name: "checked"}`, `{id: 2, name: "unchecked"}` |

Both files define `signature` with `id: 0` → **no conflict**. The merged
output will contain all three categories with IDs unchanged.

```bash
python -m src.utils.merge_coco \
    -i _annotations.coco.json _annotations.checkboxes.coco.json \
    -o _annotations.merged.json \
    --verbose
```

## Error Handling

| Situation | Behavior |
|-----------|----------|
| Fewer than 2 input files | Prints error to stderr, exits with code 1 |
| Input file not found | Prints error to stderr, exits with code 1 |
| Invalid JSON in input file | Prints error to stderr, exits with code 1 |
| Output directory does not exist | Created automatically (including parent dirs) |
